# CLAUDE.md

Guidance for Claude Code working in this repo. See `README.md` for the full
explanation of how the sync works; this file is only the rules that aren't
obvious from reading the code.

## What this repo is

Git-backed version control for Peliqan Data App scripts. `scripts/*.py` is the
source of truth for git → Peliqan: **anything merged to `main` under
`scripts/**.py` is deployed to a live Peliqan account by CI.** Treat edits
there as production changes, not local experiments.

## Don't touch

- **`scripts/.manifest.json`** — written only by the fetch/push scripts. It
  stores the sha256 hashes both scripts use to detect drift; a hand-edited
  hash causes false conflicts or a silent "nothing to sync".
- **`scripts/*.remote.py`** — conflict artifacts from `fetch`, gitignored.
  Never commit one, and never edit one expecting it to be pushed. Resolve by
  writing the final content into the real file, deleting the `.remote.py`, then
  `push_peliqan_data_apps.py --force`.
- **The dev shim at the top of each fetched script** — the ~20 lines starting
  `if 'RUN_CONTEXT' in globals():`. It's prepended by `fetch`, stripped by
  `push`, and expected byte-for-byte (see `LOCAL_DEV_SHIM` in
  `peliqan_common.py`). Edit the script *below* it; leave it alone, and never
  add a second copy.

## Running the scripts

Both `fetch_peliqan_data_apps.py` and `push_peliqan_data_apps.py` hit a live
Peliqan account with real write access. Don't run them speculatively:

- Ask before running `push` (or any `--force`). `push --dry-run` is the safe
  way to show what would happen.
- `fetch` overwrites local files when they match the manifest, so it can
  discard uncommitted work. Commit first.

## Two different credentials, similar names

- `PELIQAN_API_TOKEN` — used by fetch/push to call the Peliqan API. Also a repo
  secret for CI (a separate value from the local env var).
- `PELIQAN_API_KEY` — used only by the dev shim, when running a fetched Data
  App locally under Streamlit.

Never hardcode either into a script or commit one.

## Conventions

- Python stdlib + `requests` only for the tooling here; `requirements.txt`
  covers the tooling and the shim, not per-script imports.
- Script filenames are `<interface_id>_<slug>.py`, generated by `fetch`. Don't
  rename them: the id is how `push` knows which interface to update.
